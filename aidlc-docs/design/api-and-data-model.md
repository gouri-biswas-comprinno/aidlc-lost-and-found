# API and Data Model Design

## Report Document

Collection: `reports`

Fields:

- `title`: String, required, trimmed
- `description`: String, required, trimmed
- `type`: String, required, enum `lost | found`
- `category`: String, required, trimmed
- `location`: String, required, trimmed
- `date`: Date, required
- `contactName`: String, required, trimmed
- `contactEmail`: String, required, trimmed, basic email validation
- `status`: String, required, enum `active | resolved`, default `active`
- `createdAt`: Date, generated by Mongoose timestamps
- `updatedAt`: Date, generated by Mongoose timestamps

The MongoDB `_id` is returned as `id` in API responses when practical so the browser does not need to understand database-specific naming.

## REST Endpoints

### List Reports

`GET /api/reports`

Optional query parameters:

- `search`: case-insensitive text search across title, description, location, and category
- `type`: `lost` or `found`
- `category`: category value
- `status`: `active` or `resolved`

Response: `200` with an array of report objects.

### Get One Report

`GET /api/reports/:id`

Response: `200` with one report, `404` when no report exists, or `400` for an invalid identifier.

### Create Report

`POST /api/reports`

Body: report fields except generated timestamps. `status` may be omitted and defaults to `active`.

Response: `201` with the created report.

### Update Report

`PUT /api/reports/:id`

Body: editable report fields. The server validates the complete resulting document and preserves timestamps.

Response: `200` with the updated report, `404` when missing, or `400` for invalid input.

### Resolve Report

`PATCH /api/reports/:id/resolve`

No body required. Sets status to `resolved`.

Response: `200` with the updated report, `404` when missing, or `400` for an invalid identifier.

### Delete Report

`DELETE /api/reports/:id`

Response: `204` with no body when deleted, or `404` when missing.

## Client Service Contract

The React service module exposes small functions matching the endpoints: list reports with filters, get a report, create, update, resolve, and delete. Components do not construct fetch URLs or parse response formats themselves.

## Categories

The first version uses a fixed client dropdown for predictable filtering: `Electronics`, `Documents`, `Clothing`, `Accessories`, `Keys`, `Bags`, `Pets`, and `Other`. The API stores the selected string without requiring a second category collection.

## Query Behavior

- Omitted filters do not restrict results.
- Multiple filters are combined with logical AND.
- Search is optional and case-insensitive.
- Default list ordering is newest report first.
- Invalid filter values return `400` rather than silently returning misleading results.

## Data Validation

Validation is performed at both boundaries:

1. Express validates and normalizes incoming request data so clients receive immediate, predictable errors.
2. Mongoose validates the persisted document so invalid data cannot bypass the API layer.
